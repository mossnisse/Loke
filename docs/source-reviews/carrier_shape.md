# Source review of carrier_shape.odin

Reviewed [carrier_shape.odin](../../src/carrier_shape.odin) at `ea622efe`. It classifies borrow carriers and caches their projection paths for checking, provenance, and LLVM lowering. Keeping these type queries outside the flow solver lets all three phases share the same carrier definitions and precision budgets.

## Findings

- **P2 · Correctness, lines 157–199.** A width or depth cut can hide a synchronized borrow destination. The normal leaf path recognizes a synchronized field through a read-only pointer. The truncated path enumerates the same carrier leaves but recurses straight into each pointee and skips that check. A focused test marked a pointer field as synchronized, as in `sync.Atomic(^int)`. The destination query returned true for a record holding a read-only pointer to that cell and false after four single-field records wrapped it. Share the per-leaf destination test across both paths and retain the separate capability rule for owner writes. The probe verified the destination query. Call-site behavior still needs a Loke-level regression. [Destination query](../../src/carrier_shape.odin#L152) · [Retention consumer](../../src/provenance_retention.odin#L222) · [Retention rules](../design.md#retaining-a-borrow)
- **P2 · Determinism, lines 73–89.** The recursive map width calculation caches an answer reached while an ancestor is provisionally unkeyed. With `A :: struct { p: ^int, next: map[int]B }` and `B :: struct { next: map[int]A }`, a focused test measured `(false, true)` for `(map[int]A, map[int]B)` when queried A-first and `(true, false)` when queried B-first. Resolve a recursive group consistently, for example by recording every member of the active cycle as unkeyed and preserving that decision when unwinding. Keep the existing keyed decisions for acyclic entries. [Map width query](../../src/carrier_shape.odin#L73) · [Constant-key consumer](../../src/provenance_input.odin#L401) · [Precision rules](../design.md#minimum-provenance-precision)
- **P3 · Allocation and traversal, lines 302–314, 328–331, and 359–426.** The width guard stops a child walk after the path budget is exceeded, but the caller has already allocated the child's prefix in the semantic arena. A record with many fields still allocates prefixes for every remaining sibling and may repeat that work in the fallback walk. Stop each sibling loop once one excess path establishes overflow. Pass the smaller map width limit to the sizing walk and keep its temporary prefixes out of the semantic arena. Measure a wide-record workload before changing storage for the successful shape. [Shape fallback](../../src/carrier_shape.odin#L295) · [Prefix allocator](../../src/carrier_shape.odin#L425)

## Verification

Both correctness tests demonstrated the reported failures in an isolated copy of the reviewed compiler package. The allocation finding comes from source inspection. Reference searches found live consumers for the exported helpers and no standalone code to remove.
